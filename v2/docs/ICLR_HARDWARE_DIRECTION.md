# Joint solver and implementation search

The [September 6 submission assessment and attack plan](ICLR_SUBMISSION_ATTACK_PLAN.md)
audits this direction against current results, official ICLR guidance, and public
reviews of related oral and rejected papers. In particular, joint-search gains
remain unproven, and certificate cadence alone is established solver engineering
(PDLP already exposes termination-check frequency).

Execution has started. The [development protocol](SOLVER_INTERACTION_PROTOCOL.md)
and [claim ledger](ICLR_CLAIM_LEDGER.md) define the first milestone: reconcile the
manuscript with the implementation and measure distinct TV solver maps against
a compiled float64, K=64 baseline. Results and the next decision are recorded in
the [September 6 execution report](../results/attack_plan_20260906/REPORT.md).

The paper can center on searching an executable solver recipe conditioned on
a problem distribution and target device. A recipe contains the mathematical
iteration, its wrappers, a kernel implementation, precision, and certificate
cadence. Fitness is measured time to the declared original-problem numerical
criterion, with non-solves explicitly censored. Compilation and preparation
costs must also be reported, along with the assumed reuse count.

For a fixed class D, device h, and tolerance epsilon, the objective is
`min_recipe E[p ~ D] time_to_certificate(recipe, p, h, epsilon)` subject to
the mathematical construction gate and implementation admission. This is an
empirical objective, not a claim that the arithmetic is exact or that the
search returns an optimal algorithm.

## Why joint search might matter

A solver with fewer iterations can have a more expensive update, a larger
state, or fewer fusion opportunities. A kernel can change the balance between
update time and certificate time. Reducing certificate frequency can delay
detection enough to change which solver wins. Precision can change attainable
tolerance. These interactions make independent optimization potentially
suboptimal; the interaction must be measured rather than assumed.

The current implementation can search PDHG parameters and wrappers together
with generated CSR update templates and cadence. For TV/OCT the mathematical
scheme gene is meaningful because the smooth component is nonzero; the
current TV kernels are still generated by XLA. On standard LP, PDHG and
Condat-Vu coincide, so different labels cannot establish structural discovery.

## The decisive experiment

Freeze the problem distribution, train/validation/final partitions, tolerance,
devices, compiler versions, search budget, and timing contract. Compare:

1. Fixed solver and default implementation.
2. Algorithm search with the implementation fixed.
3. Kernel/policy search with the algorithm fixed.
4. Sequential algorithm-then-kernel search, and its reverse.
5. Joint search over the same candidate spaces and total fresh-evaluation budget.

The full factorial catalog and report compute all these selections.
It is an inexpensive interaction diagnostic, not a
budget-matched evolutionary discovery result. A joint selection equal to
the sequential selection is a valid result and must be reported.

For the proposer, compare independent random search, typed population
mutation, and LLM proposals under none/identity/measured hardware context.
Use separate RNG streams, count all fresh evaluations, and report model calls,
tokens, fallbacks, compile time, and search time. Do not infer an LLM advantage
from total system speedup. The initial two-seed, eight-evaluation CPU pilot
does not establish one.

## Kernel creation and assurance

The bounded CUDA generator creates row-thread and row-warp CSR update
specializations, with explicit block sizes. Its two kernels fuse the primal
and dual matvecs with the corresponding vector operations. They retain the
dependency between primal and dual updates and the original f64 certificate.
Hawkeye motivates supplying executable optimizations with measured costs,
then composing transformations guided by profiling. Its approach does not
justify predicting a gain from device specifications alone.

The construction gate checks the mathematical recipe before native-kernel
admission. Admission compares generated and reference updates; independent
end-to-end checks validate returned original coordinates. These are distinct
assurance levels. Numerical tests are not a formal proof of compiler or
floating-point refinement. Arbitrary LLM-generated CUDA needs a broader
admission suite and is not implemented in this prototype.

## Defensible paper shape

Working title: **OptEvolve: Hardware-Aware Search for Certified Optimization
Solvers**. A title claiming joint discovery requires an end-to-end joint search
experiment that establishes its contribution.

Lead with the executable-recipe mechanism, then the strongest held-out number
and a control isolating its cause. The cadence finding can support that story:
certificate evaluation itself changes the cost landscape. Treat existing
algorithm families and the feedback loop as prior art. A negative feedback
ablation can be a secondary controlled finding, without claiming the first
repair-versus-resampling comparison.

The immediate results are diagnostic and small. The LP calibration failure
stands, and the original final holdout is untouched. Scale the hardware
comparison only after determining whether the joint-versus-sequential gap
exists. If it does not, center the paper on certificate-aware execution search
and report the absence of a joint-search advantage explicitly.

References to verify and cite in the manuscript: Hawkeye (ICML 2026,
https://icml.cc/virtual/2026/82754), ReEvo (arXiv:2402.01145), AutoOPT, and the
Yoon-lineage proof-discovery work. The survey's AutoOPT eight-hour number
describes a campaign and must not be used as verifier latency. Mutation-chain
collapse without selection is a hypothesis for our population behavior, not
an established explanation. Recent repair-versus-resampling prior art also
precludes an unqualified first-ablation claim.
